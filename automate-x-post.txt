===== 2. KARPATHY STYLE =====

𝗧𝗵𝗲 𝗠𝗲𝗺𝗼𝗿𝘆 𝗦𝗵𝗼𝘂𝗹𝗱 𝗢𝘂𝘁𝗹𝗶𝘃𝗲 𝗧𝗵𝗲 𝗖𝗵𝗮𝘁 𝗔𝗽𝗽

Today each chat client is a little computer with its own disk. Claude Desktop has one, Cursor has another, and nothing is mounted between them. So you become the sync protocol, copying context from window to window by hand.

autoMate flips that around. One process on your machine (127.0.0.1:8765) owns a folder, ~/.𝚊𝚞𝚝𝚘𝚖𝚊𝚝𝚎/, backed by SQLite. Where I'd be careful, imo:

• 𝗧𝗵𝗲 𝘀𝗮𝗺𝗲 𝘁𝗼𝗸𝗲𝗻 𝗿𝗲𝗮𝗰𝗵𝗲𝘀 𝘀𝗵𝗲𝗹𝗹.𝗲𝘅𝗲𝗰. A shared notebook and a remote shell are very different risk levels, and here they sit behind one Bearer token.
• 𝗦𝗰𝗼𝗽𝗲. It also ships desktop control, browser control, 𝟯𝟭 𝗦𝗮𝗮𝗦 𝗶𝗻𝘁𝗲𝗴𝗿𝗮𝘁𝗶𝗼𝗻𝘀 and 𝟮𝟱 𝗟𝗟𝗠 𝗽𝗿𝗼𝘃𝗶𝗱𝗲𝗿𝘀. That's a lot for a young codebase to keep correct.
• 𝗘𝘃𝗶𝗱𝗲𝗻𝗰𝗲. There are no evals in the README, so "it remembers" is a design claim right now.

It's also an old idea in new clothes. Basic Memory does the memory part with plain Markdown files.

𝗕𝗲𝗳𝗼𝗿𝗲 𝘆𝗼𝘂 𝘁𝗿𝘂𝘀𝘁 𝗶𝘁, 𝗿𝘂𝗻 𝘁𝗵𝗶𝘀

• 𝗪𝗿𝗶𝘁𝗲 𝟮𝟬 𝗳𝗮𝗰𝘁𝘀 through one client, in your own words
• 𝗔𝘀𝗸 𝗳𝗼𝗿 𝘁𝗵𝗲𝗺 𝗳𝗿𝗼𝗺 𝗮 𝘀𝗲𝗰𝗼𝗻𝗱 𝗰𝗹𝗶𝗲𝗻𝘁, phrased differently each time
• 𝗦𝗲𝘁 𝗮 𝗯𝗮𝘀𝗲𝗹𝗶𝗻𝗲: the same 20 questions against a plain text file pasted into context
• 𝗖𝗼𝗺𝗽𝗮𝗿𝗲 𝗵𝗶𝘁 𝗿𝗮𝘁𝗲𝘀, then read the traces for every miss and see what 𝚜𝚎𝚊𝚛𝚌𝚑.𝚏𝚒𝚗𝚍 was actually asked

If the plain file wins, you've saved yourself a server. If autoMate wins, you now have a number to quote.

===== 6. ETHAN MOLLICK STYLE =====

𝗪𝗵𝗼 𝗦𝗵𝗼𝘂𝗹𝗱 𝗛𝗼𝗹𝗱 𝗬𝗼𝘂𝗿 𝗔𝗜'𝘀 𝗠𝗲𝗺𝗼𝗿𝘆?

Most people who use AI seriously now use more than one tool. And each tool has its own memory, like a set of assistants who never talk to each other. You brief one in the morning and start over with the next.

One answer is to stop keeping memory inside the assistants at all.

That's the idea behind autoMate, an open-source project whose README calls it "𝘈 𝘴𝘮𝘢𝘳𝘵 𝘕𝘈𝘚 𝘧𝘰𝘳 𝘈𝘐." Think of it as 𝗮 𝗳𝗶𝗹𝗶𝗻𝗴 𝗰𝗮𝗯𝗶𝗻𝗲𝘁 𝗶𝗻 𝘆𝗼𝘂𝗿 𝗼𝘄𝗻 𝗵𝗼𝘂𝘀𝗲. Any assistant you let in can open the drawers: your notes, your files, a list of facts worth remembering, your reminders. It runs on your computer and stores everything in a folder there.

Hire a different assistant next month and the cabinet stays where it is.

There's a clever touch in the setup. One button copies instructions that are written for an AI, so you can hand them to your assistant and ask it to connect itself.

Now the other side.

𝗪𝗲 𝗱𝗼𝗻'𝘁 𝗸𝗻𝗼𝘄 𝗵𝗼𝘄 𝘄𝗲𝗹𝗹 𝗶𝘁 𝘄𝗼𝗿𝗸𝘀. The project publishes no tests of whether an assistant reliably finds what another one saved. The search is keyword-based, which is fast but can miss a note that uses different words.

The cabinet also comes with keys to the rest of the house. The same access that reads notes can run commands on your computer, and the project's own README warns you to guard that access like a password.

It isn't alone either. Basic Memory and Mem0's OpenMemory are working on the same problem in simpler forms.
