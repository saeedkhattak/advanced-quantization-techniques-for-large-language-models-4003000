===== 1. Story =====

𝗢𝗿𝗰𝗮 𝗪𝗮𝗻𝘁𝘀 𝗬𝗼𝘂𝗿 𝗖𝗼𝗱𝗶𝗻𝗴 𝗔𝗴𝗲𝗻𝘁𝘀 𝗧𝗼 𝗪𝗼𝗿𝗸 𝗟𝗶𝗸𝗲 𝗔 𝗧𝗲𝗮𝗺

You start Claude Code on a bug. Then a second terminal for a refactor. Then a third because CI broke. Ten minutes later you've lost track of which tab is waiting on you.

Orca is an open-source desktop app from Stably AI built for that mess. Its README sums it up in one line: "𝘉𝘰𝘵𝘴 𝘪𝘯𝘴𝘪𝘥𝘦 𝘺𝘰𝘶𝘳 𝘢𝘨𝘦𝘯𝘵 𝘐𝘋𝘌."

𝗧𝗵𝗲 𝗶𝗱𝗲𝗮 𝗶𝘀 𝘀𝗶𝗺𝗽𝗹𝗲: 𝗼𝗻𝗲 𝗮𝗴𝗲𝗻𝘁 𝗽𝗲𝗿 𝘁𝗮𝘀𝗸, 𝗲𝗮𝗰𝗵 𝗶𝗻 𝗶𝘁𝘀 𝗼𝘄𝗻 𝗴𝗶𝘁 𝘄𝗼𝗿𝗸𝘁𝗿𝗲𝗲, 𝗮𝗹𝗹 𝗶𝗻 𝗼𝗻𝗲 𝘄𝗶𝗻𝗱𝗼𝘄.

Each task gets its own worktree, so agents don't write over each other's files. You can run them as a chat UI or the raw CLI and move a conversation between the two.

For a big job you hand the task to one coordinator agent. It splits the work, starts worker agents in their own workspaces and brings the results back.

When an agent finishes, you review the diff inside Orca, leave a note on an exact line, and send it back. Failing checks and PR review comments can go back to the agent the same way.

Then there are the bots. You ask one in Slack, Linear or GitHub to fix a bug, and the README says you come back to a tested pull request. Bots can run on a schedule ("every weekday at 9") or fire when a PR opens, a check fails or a webhook comes in.

𝗙𝗼𝗿 𝘂𝘀𝗲𝗿𝘀: it runs on macOS, Windows and Linux, with iOS and Android apps that ping you when an agent needs input. Agents can run on an SSH host or a Remote Orca Server, so they keep going when your laptop sleeps.

𝗙𝗼𝗿 𝗯𝘂𝗶𝗹𝗱𝗲𝗿𝘀: it isn't tied to one model. It runs on your own Claude Code or Codex subscription, and the README lists 𝗺𝗼𝗿𝗲 𝘁𝗵𝗮𝗻 𝟯𝟬 𝗖𝗟𝗜 𝗮𝗴𝗲𝗻𝘁𝘀, plus "any CLI agent". A bot's personality and memory are plain Markdown files (𝚂𝙾𝚄𝙻.𝚖𝚍, 𝙼𝙴𝙼𝙾𝚁𝚈.𝚖𝚍) you can read and edit. There's also an Orca CLI, so agents can create worktrees and start workers themselves.

It isn't the first tool here. Claude Squad (AGPL-3.0) manages several terminal agents in separate workspaces. Vibe Kanban (Apache-2.0) did a board for agent tasks and is now sunsetting, per its README. Orca goes wider: bots, mobile, remote machines, review.

A few caveats. Every feature above is the team's own description. "Tested pull request" is their claim, and the tests are only as good as your repo's. Worktrees separate files, not shared things like a local database or a port. The app collects 𝗮𝗻𝗼𝗻𝘆𝗺𝗼𝘂𝘀 𝘂𝘀𝗮𝗴𝗲 𝗱𝗮𝘁𝗮 by default, with an opt-out. And it moves fast: 𝘁𝘄𝗼 𝗱𝗲𝘀𝗸𝘁𝗼𝗽 𝗿𝗲𝗹𝗲𝗮𝘀𝗲𝘀 𝗼𝗻 𝟮𝟰 𝗡𝗼𝘃 𝗮𝗹𝗼𝗻𝗲 (latest v1.4.274), so expect things to change under you.

It's MIT licensed, with 𝟭𝟯𝟳.𝟴𝗸 𝗚𝗶𝘁𝗛𝘂𝗯 𝘀𝘁𝗮𝗿𝘀 as of 25 Nov 2026.

===== 2. Karpathy style =====

𝗢𝗿𝗰𝗮 𝗔𝗻𝗱 𝗧𝗵𝗲 𝗦𝗵𝗮𝗽𝗲 𝗢𝗳 𝗔𝗻 𝗔𝗴𝗲𝗻𝘁 𝗜𝗗𝗘

Been looking at Orca, the open-source (MIT) desktop app from Stably AI for running lots of coding agents at once.

The feature list is long. Parallel worktrees, diff review, a mobile app, remote hosts, bots in Slack. 𝗕𝘂𝘁 𝗜 𝘁𝗵𝗶𝗻𝗸 𝘁𝗵𝗲 𝗶𝗻𝘁𝗲𝗿𝗲𝘀𝘁𝗶𝗻𝗴 𝗽𝗮𝗿𝘁 𝗶𝘀𝗻'𝘁 𝗮𝗻𝘆 𝘀𝗶𝗻𝗴𝗹𝗲 𝗳𝗲𝗮𝘁𝘂𝗿𝗲, 𝗶𝘁'𝘀 𝘄𝗵𝗮𝘁 𝘁𝗵𝗲 𝗮𝗽𝗽 𝗮𝘀𝘀𝘂𝗺𝗲𝘀 𝗮𝗯𝗼𝘂𝘁 𝘆𝗼𝘂.

It assumes you aren't writing most of the code. You're dispatching it.

That changes what the main screen should be. An editor is built around one file and one cursor. Orca is built around many tasks, each in its own git worktree, each with its own agent, and a list of which ones need you.

The analogy I keep coming back to is a kitchen pass. The cooks (Claude Code, Codex, any of the 𝟯𝟬+ 𝗖𝗟𝗜 𝗮𝗴𝗲𝗻𝘁𝘀 it lists) do the work at their stations. The person at the pass doesn't cook. They check each plate, send some back with a note, and keep orders moving. Orca's diff review is literally that: comment on a line, send it back to the agent.

The bots push it one step further. You ask in Slack, Linear or GitHub, and per the README you come back to a tested PR. A bot's memory is plain Markdown (𝙼𝙴𝙼𝙾𝚁𝚈.𝚖𝚍, 𝚂𝙾𝚄𝙻.𝚖𝚍), which I like a lot. Readable state beats a hidden vector store, imo.

What I'd be careful about. The bottleneck in this setup is review, not generation. Ten agents producing ten diffs is only a win if you can actually judge ten diffs. "Tested" is only as strong as the tests in your repo. And worktrees isolate files, not your local database or ports.

Also, everything here is the team's own description. They ship very fast (𝘃𝟭.𝟰.𝟮𝟳𝟰 𝗼𝗻 𝟮𝟰 𝗡𝗼𝘃 𝟮𝟬𝟮𝟲, two desktop releases that day), so the details will drift.

What I'd actually want to see: numbers on how often a bot's PR gets merged unchanged, versus sent back. 𝘛𝘩𝘢𝘵'𝘴 𝘵𝘩𝘦 𝘮𝘦𝘵𝘳𝘪𝘤 𝘵𝘩𝘢𝘵 𝘵𝘦𝘭𝘭𝘴 𝘺𝘰𝘶 𝘸𝘩𝘦𝘵𝘩𝘦𝘳 𝘵𝘩𝘦 𝘱𝘢𝘴𝘴 𝘪𝘴 𝘸𝘰𝘳𝘬𝘪𝘯𝘨.

• 𝗜𝘀𝗼𝗹𝗮𝘁𝗶𝗼𝗻 𝗯𝗲𝘆𝗼𝗻𝗱 𝗳𝗶𝗹𝗲𝘀. Worktrees don't separate a shared local database or a port.
• 𝗜𝗻𝗱𝗲𝗽𝗲𝗻𝗱𝗲𝗻𝘁 𝗻𝘂𝗺𝗯𝗲𝗿𝘀. Every feature claim is the team's own. There is no public merge-rate or success-rate figure yet.

So treat it like any other agent setup and measure it. A simple recipe:

1. Pick 𝟮𝟬 𝗰𝗹𝗼𝘀𝗲𝗱 𝗶𝘀𝘀𝘂𝗲𝘀 from your repo with known fixes.
2. Baseline: run them through one agent in a single terminal. Record pass rate and how many review rounds each took.
3. Run the same 20 through Orca, with bots or a coordinator plus workers.
4. Compare merged-without-changes, review rounds, and your time spent reviewing.
5. Read the traces for the failures. Check what the bot wrote in 𝙼𝙴𝙼𝙾𝚁𝚈.𝚖𝚍 too.

===== 6. Ethan Mollick style =====

𝗪𝗵𝗮𝘁 𝗛𝗮𝗽𝗽𝗲𝗻𝘀 𝗪𝗵𝗲𝗻 𝗔 𝗗𝗲𝘃𝗲𝗹𝗼𝗽𝗲𝗿 𝗛𝗮𝘀 𝗧𝗲𝗻 𝗔𝘀𝘀𝗶𝘀𝘁𝗮𝗻𝘁𝘀 𝗜𝗻𝘀𝘁𝗲𝗮𝗱 𝗢𝗳 𝗢𝗻𝗲?

AI coding agents can now write a lot of code on their own. The new question is what work looks like when one person runs many of them at the same time.

Orca is one answer. It's a free, open-source app from a startup called Stably AI that lets a developer run many AI coding assistants side by side.

Think of a manager with a team of contractors. Each contractor gets their own copy of the project to work on, so nobody overwrites anyone else. The manager doesn't do the work. They hand out tasks, check what comes back, write notes on what's wrong, and send it back for another pass.

That's roughly what Orca does. You can even message a "bot" in Slack and, according to the company, come back later to a finished, tested change ready for review. There's a phone app that pings you when one of them needs a decision.

Developers seem interested. The project has 𝟭𝟯𝟳.𝟴𝗸 𝘀𝘁𝗮𝗿𝘀 𝗼𝗻 𝗚𝗶𝘁𝗛𝘂𝗯 (a rough measure of attention) as of 25 Nov 2026, and the team ships updates almost every day.

What we don't know yet matters more. The features are the company's own description, and there is no independent public data yet on how often these bots' work gets accepted as is. "Tested" only means the project's existing checks passed, which can miss a lot. And more assistants means more work to review. 𝗔 𝗺𝗮𝗻𝗮𝗴𝗲𝗿 𝘄𝗶𝘁𝗵 𝘁𝗲𝗻 𝗰𝗼𝗻𝘁𝗿𝗮𝗰𝘁𝗼𝗿𝘀 𝘀𝘁𝗶𝗹𝗹 𝗵𝗮𝘀 𝘁𝗼 𝗰𝗵𝗲𝗰𝗸 𝘁𝗲𝗻 𝗷𝗼𝗯𝘀.

So the evidence so far is mostly about adoption, not outcomes.
