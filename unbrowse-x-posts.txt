===== 0. PAPER POST (paper-to-tweet format) =====

Most AI agents use websites the slow way.

They open a browser, load the full page, read thousands of tokens of HTML and click around. Every agent repeats the same work on the same site.

There is a faster way: call the site's internal API (the hidden endpoints the page itself uses to get its data). You get clean JSON back, with no page to read.

But there is a catch. These APIs are not documented. Someone has to find them first, work out the inputs, and handle tokens and logins. And they can change without warning.

A paper from the Unbrowse team ("Internal APIs Are All You Need") solves this with a shared registry of learned routes.

The idea is simple: learn a site once, then replay it.

1. The agent asks for a task, like "top stories on Hacker News".
2. Unbrowse searches your private tools, then a public registry of sites already learned.
3. If there is a match, it replays the site's own HTTP requests. No browser.
4. If not, the agent does the task once in a recorded cloud browser, and the traffic is compiled into a one-call tool.

The system works out by itself which request fields are inputs and which are fixed.

How it works:

→ It records two sessions with different inputs and compares them. The fields that change are the inputs.
→ It traces tokens (like CSRF values) back to the response that produced them, so a multi-step flow replays as one call.
→ A run counts as success only when the result is verified. HTTP 200 alone is not enough.
→ Only read-only routes with no secrets go to the public registry. Logins and writes are never shared.

Results in the paper across 94 production domains (self-reported, compared with Playwright):

• 950 ms mean vs 3,404 ms with browser automation
• 3.6x faster on average, 5.4x at the median
• 90–96% lower cost per task
• ~8,000 tokens of DOM down to ~200 tokens of JSON

The team's newer test on 100 real sites is more modest: 42 worked on warm replay, 2 gave wrong results, and the rest failed or could not be learned.

What I find interesting as someone building agents: the browser becomes the fallback, not the default. But only the CLI and SDK are open source. The service that does the work is hosted, so check that before you depend on it.

===== 6. ETHAN MOLLICK STYLE =====

𝗪𝗵𝗮𝘁 𝗜𝗳 𝗔𝗜 𝗔𝗴𝗲𝗻𝘁𝘀 𝗡𝗲𝘃𝗲𝗿 𝗡𝗲𝗲𝗱𝗲𝗱 𝘁𝗼 𝗦𝗲𝗲 𝗮 𝗪𝗲𝗯 𝗣𝗮𝗴𝗲?

When an AI agent uses a website today, it behaves like a customer walking through a shop. It looks at the shelves, reads the labels and finds the till. That's slow, and it costs money, because the AI has to read the whole page.

But every shop has a stockroom door. The website itself fetches its data through small behind-the-scenes requests, and those are much quicker to use.

Unbrowse is a tool that 𝗹𝗲𝗮𝗿𝗻𝘀 𝘁𝗵𝗼𝘀𝗲 𝗿𝗲𝗾𝘂𝗲𝘀𝘁𝘀 𝗼𝗻𝗰𝗲 𝗮𝗻𝗱 𝗹𝗲𝘁𝘀 𝗮𝗴𝗲𝗻𝘁𝘀 𝗿𝗲𝘂𝘀𝗲 𝘁𝗵𝗲𝗺. One agent does the task in a recorded browser, and after that the same task runs without a browser at all.

The evidence points both ways.

On one side, the team's paper reports that across 94 websites this took 𝘂𝗻𝗱𝗲𝗿 𝗮 𝘀𝗲𝗰𝗼𝗻𝗱 𝗼𝗻 𝗮𝘃𝗲𝗿𝗮𝗴𝗲, 𝗮𝗴𝗮𝗶𝗻𝘀𝘁 𝟯.𝟰 𝘀𝗲𝗰𝗼𝗻𝗱𝘀 with a browser. It also cut what the AI had to read from about 8,000 tokens to about 200.
