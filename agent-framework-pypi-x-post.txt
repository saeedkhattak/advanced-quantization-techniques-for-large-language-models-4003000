On 17 Nov at 20:35 UTC, a new version of 𝚊𝚐𝚎𝚗𝚝-𝚏𝚛𝚊𝚖𝚎𝚠𝚘𝚛𝚔 showed up on PyPI. It's Microsoft's Python package for building AI agents, at about 𝟰𝟭,𝟬𝟬𝟬 𝗱𝗼𝘄𝗻𝗹𝗼𝗮𝗱𝘀 𝗮 𝘄𝗲𝗲𝗸.

Version 1.26.1 carried a credential stealer. A second one, 1.26.2, followed 33 minutes later. By 21:30 UTC both were gone.

Wiz Research has now traced how it got out, and that part is worse than the malware.

𝗧𝗵𝗲 𝗮𝘁𝘁𝗮𝗰𝗸𝗲𝗿 𝗮𝗽𝗽𝗲𝗮𝗿𝘀 𝘁𝗼 𝗵𝗮𝘃𝗲 𝗵𝗮𝗱 𝗮 𝗰𝗹𝗶𝗲𝗻𝘁 𝗰𝗲𝗿𝘁𝗶𝗳𝗶𝗰𝗮𝘁𝗲 𝗮𝗻𝗱 𝗽𝗿𝗶𝘃𝗮𝘁𝗲 𝗸𝗲𝘆 𝗳𝗼𝗿 𝗘𝗦𝗥𝗣, the internal Microsoft service that signs and publishes this package. Their first upload, from AWS, was blocked by ESRP's IP filtering. The second, from Microsoft-owned IP space, went through. How they got the certificate is still unknown.

The payload hid in a .𝚙𝚝𝚑 file, which Python runs every time it starts. 𝗬𝗼𝘂 𝗱𝗶𝗱𝗻'𝘁 𝗻𝗲𝗲𝗱 𝘁𝗼 𝗶𝗺𝗽𝗼𝗿𝘁 𝘁𝗵𝗲 𝗽𝗮𝗰𝗸𝗮𝗴𝗲. Any Python process in that environment ran it.

It went after Azure first:

• 𝗦𝗲𝗰𝗿𝗲𝘁𝘀 𝗶𝗻 𝗲𝗻𝘃𝗶𝗿𝗼𝗻𝗺𝗲𝗻𝘁 𝘃𝗮𝗿𝗶𝗮𝗯𝗹𝗲𝘀, plus up to 300 other processes' environments
• 𝗖𝗿𝗲𝗱𝗲𝗻𝘁𝗶𝗮𝗹 𝗳𝗶𝗹𝗲𝘀: Azure CLI, npm, pip, git, Docker, Hugging Face (60 files, 80 in the second version)
• 𝗔𝘇𝘂𝗿𝗲 𝗺𝗮𝗻𝗮𝗴𝗲𝗱-𝗶𝗱𝗲𝗻𝘁𝗶𝘁𝘆 𝘁𝗼𝗸𝗲𝗻𝘀 for 12 services, including Key Vault and Storage
• 𝗚𝗶𝘁𝗛𝘂𝗯 𝗔𝗰𝘁𝗶𝗼𝗻𝘀 𝗢𝗜𝗗𝗖 𝘁𝗼𝗸𝗲𝗻𝘀 in 1.26.2, which can turn into Azure access with no stored secret at all

There's an odd AI twist. The tooling calls itself Cairn, an open-source AI penetration-testing framework, and the attacker tested the stealer on their own machine first. According to Wiz, that run captured what looks like a Pi coding-agent setup backed by a GLM model.

The damage looks small, for now. The data went to a free public webhook that keeps 100 requests at most. Wiz analysed the 50 stored there and found 𝘁𝗵𝗿𝗲𝗲 𝘂𝗻𝗶𝗾𝘂𝗲 𝘃𝗶𝗰𝘁𝗶𝗺𝘀 whose data actually left. The rest came from the attacker, sandboxes and security scanners.
