===== Story =====

𝗬𝗼𝘂𝗿 𝗔𝗜 𝗔𝗴𝗲𝗻𝘁𝘀 𝗔𝗿𝗲 𝗪𝗼𝗿𝗸𝗶𝗻𝗴. 𝗡𝗼𝗯𝗼𝗱𝘆 𝗞𝗻𝗼𝘄𝘀 𝗪𝗵𝗼'𝘀 𝗗𝗼𝗶𝗻𝗴 𝗪𝗵𝗮𝘁.

Two agents grab the same bug.
A third needs your sign-off, can't ask, and guesses.
The update in Slack is signed by a bot, not by the agent or the person who started it.

That's what a team of agents looks like right now. Vercel's answer, shipped this week, is a message board. 𝗦𝗲𝗿𝗶𝗼𝘂𝘀𝗹𝘆, 𝗮 𝗺𝗲𝘀𝘀𝗮𝗴𝗲 𝗯𝗼𝗮𝗿𝗱.

Everyone else put agents into chat this year:

• 𝗦𝗹𝗮𝗰𝗸 𝗖𝗼𝗱𝗲: tag Claude, Devin, Copilot or Vercel and the agent opens a code channel for the task, archived when it's done.
• 𝗖𝗹𝗮𝘂𝗱𝗲 𝗧𝗮𝗴: @Claude in Slack works under its own identity, with access an admin sets per channel.
• 𝗢𝗽𝗲𝗻𝗔𝗜: workspace agents run on Codex in the cloud, inside ChatGPT and Slack.
• 𝗠𝗶𝗰𝗿𝗼𝘀𝗼𝗳𝘁 𝗧𝗲𝗮𝗺𝘀: a Channel Agent with channel memory. Still in preview, Copilot licence needed.

All of them answer one question: 𝗵𝗼𝘄 𝗱𝗼𝗲𝘀 𝗮 𝗽𝗲𝗿𝘀𝗼𝗻 𝗵𝗮𝗻𝗱 𝘄𝗼𝗿𝗸 𝘁𝗼 𝗮𝗻 𝗮𝗴𝗲𝗻𝘁?

Vercel Board answers a different one: 𝗵𝗼𝘄 𝗱𝗼 𝟭𝟬 𝗮𝗴𝗲𝗻𝘁𝘀 𝗮𝗻𝗱 𝟱 𝗽𝗲𝗼𝗽𝗹𝗲 𝘀𝗵𝗮𝗿𝗲 𝘄𝗼𝗿𝗸 𝘄𝗶𝘁𝗵𝗼𝘂𝘁 𝘁𝗿𝗶𝗽𝗽𝗶𝗻𝗴 𝗼𝘃𝗲𝗿 𝗲𝗮𝗰𝗵 𝗼𝘁𝗵𝗲𝗿?

"𝗰𝗹𝗮𝘂𝗱𝗲 𝘃𝗶𝗮 𝗷𝘂𝗹𝗶𝗮𝗻." Every message shows the agent and whose login it's running on. Deployments and CI runs post as themselves too, checked by their tokens.

𝗢𝗻𝗲 𝗷𝗼𝗯, 𝗼𝗻𝗲 𝗼𝘄𝗻𝗲𝗿. An agent claims a task on a timed lease, 𝟭𝟱 𝗺𝗶𝗻𝘂𝘁𝗲𝘀 𝗯𝘆 𝗱𝗲𝗳𝗮𝘂𝗹𝘁. Go quiet and you lose it. Tasks can wait on other tasks, or sit "blocked" until a person answers.

𝗔𝗴𝗲𝗻𝘁𝘀 𝗰𝗮𝗻 𝘄𝗮𝗶𝘁 𝗳𝗼𝗿 𝘆𝗼𝘂. 𝚟𝚋 𝚠𝚊𝚒𝚝 pauses an agent until someone replies, on the board, in Slack or on GitHub, because the threads sync both ways.

Vercel says it built Board first for its own swarm of security agents, then rebuilt v0's software factory on it.

Now the part people will argue about. 𝗜𝘀 𝗶𝘁 𝗼𝗽𝗲𝗻 𝘀𝗼𝘂𝗿𝗰𝗲?

• 𝗬𝗲𝘀, 𝗔𝗽𝗮𝗰𝗵𝗲-𝟮.𝟬: the SDK, the CLI, a local SQLite board, the inspector, the Slack/GitHub/Linear sync code and the templates.
• 𝗡𝗼: the hosted board. It lives in Vercel's API, and the "nothing to deploy" magic assumes your team is on Vercel.
• 𝗢𝗳𝗳 𝗩𝗲𝗿𝗰𝗲𝗹: run 𝚟𝚋 𝚜𝚎𝚛𝚟𝚎 on your machine or your tailnet, or write your own backend. You lose the serverless wake-ups.

To be fair, leasing tasks to agents isn't a new idea. Open-source tools like MCP Agent Mail already give agents inboxes and file leases. What's new is a platform shipping identity, leases, waits and chat sync as one piece.

It's experimental, and it's v0.53.

===== Karpathy style =====

𝗧𝗵𝗲 𝗠𝗼𝘀𝘁 𝗜𝗺𝗽𝗼𝗿𝘁𝗮𝗻𝘁 𝗪𝗼𝗿𝗱 𝗶𝗻 𝗩𝗲𝗿𝗰𝗲𝗹 𝗕𝗼𝗮𝗿𝗱 𝗜𝘀 "𝗩𝗶𝗮"

Claude Tag posts as Claude.
Vercel Board posts as 𝘤𝘭𝘢𝘶𝘥𝘦 𝘷𝘪𝘢 𝘫𝘶𝘭𝘪𝘢𝘯.

𝗧𝗵𝗮𝘁 𝗼𝗻𝗲 𝘄𝗼𝗿𝗱 𝗶𝘀 𝗺𝗼𝘀𝘁 𝗼𝗳 𝘄𝗵𝗮𝘁'𝘀 𝗶𝗻𝘁𝗲𝗿𝗲𝘀𝘁𝗶𝗻𝗴 𝗵𝗲𝗿𝗲, 𝗶𝗺𝗼.

An agent acting in the world has two identities. What it is, and whose authority it's borrowing. Many agent-in-chat setups collapse them. Claude Tag, for example, runs as its own identity on credentials an admin sets for the channel, and keeps a log of who asked for what. That's a sensible design for a shared team bot.

Board keeps both on every message. The person (or deployment, or CI run) is verified by an OIDC token. The agent is a named profile on top. It's like git separating author from committer, except the board checks it.

Once you see agents that way, the rest of Board reads like an operating system for them:

• 𝗔 𝗹𝗼𝗰𝗸 𝘄𝗶𝘁𝗵 𝗮 𝘁𝗶𝗺𝗲𝗼𝘂𝘁. A task claim is a lease, 𝟭𝟱 𝗺𝗶𝗻𝘂𝘁𝗲𝘀 𝗯𝘆 𝗱𝗲𝗳𝗮𝘂𝗹𝘁. Stall and your late writes fail with 𝚌𝚕𝚊𝚒𝚖_𝚕𝚘𝚜𝚝.
• 𝗔 𝗯𝗹𝗼𝗰𝗸𝗶𝗻𝗴 𝗰𝗮𝗹𝗹. 𝚟𝚋 𝚠𝚊𝚒𝚝 sleeps until a reply lands. An agent can ask a person and simply pause.
• 𝗜𝗻𝘁𝗲𝗿𝗿𝘂𝗽𝘁𝘀. Watchers wake a function when a matching message arrives. Nobody polls.
• 𝗗𝗲𝗽𝗲𝗻𝗱𝗲𝗻𝗰𝗶𝗲𝘀. A task can wait on others, or be held for a person.

Slack, Teams and ChatGPT started with people and added agents. Board starts from the agents and syncs Slack, GitHub and Linear in so people can join from where they already are.

The licensing is a split worth knowing. SDK, CLI, local board and sync code are 𝗔𝗽𝗮𝗰𝗵𝗲-𝟮.𝟬. The zero-setup hosted board is Vercel's API. Off Vercel you run 𝚟𝚋 𝚜𝚎𝚛𝚟𝚎 yourself.

It's experimental, and nobody has published outcome numbers yet.
